# Scenario: Interview Judgment

## User

```text
面试官问我为什么建议业务做 A。我当时说模型显示 A 更好，所以我建议做 A。
但我感觉这个回答很薄，不知道怎么补。
```

## What CCC Should Notice

- 模型输出不等于用户判断。
- 不能把“模型显示 A 更好”包装成成熟业务判断。
- 需要追问用户当时看到了什么信号、担心什么风险、比较过哪些替代方案。
- 如果用户只有事后复盘，也要标注为 retrospective，而不是 used_at_time。

## Example Response

```text
我先不把这段写成“你具备成熟业务判断”。

目前能确认：
- 你参考了模型结果
- 你给出了 A 方向建议
- 但你的判断依据、取舍和风险意识还没说清

需要补 3 个问题：
1. 除了模型结果，你当时还看了哪些业务信号？
2. 为什么不是 B 或 C？你排除了什么？
3. 如果后来发现 A 的成本更高，你会用什么条件改变判断？

临时判断层级：
Judgment Depth：J1-J2 待确认
Methodology Maturity：M1 待确认
```

## Why This Matters

业务面试里，面试官往往不是只问结果，而是在看候选人能否解释判断过程。CCC 应该帮助用户还原真实判断，不替用户发明一个漂亮但不存在的方法论。
