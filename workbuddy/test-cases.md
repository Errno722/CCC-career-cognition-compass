# CCC WorkBuddy Test Cases

用这些测试用例检查 WorkBuddy 部署是否稳定。每个用例都不要使用真实个人材料。

## 1. 打招呼

```text
你好
```

期望：

- 介绍 CCC 是 Career Cognition Compass；
- 说明可以直接发送混乱文字、语音转文字、JD、简历片段；
- 提醒脱敏；
- 不输出一大段功能清单。

## 2. 混乱开局

```text
我现在很乱，gap 一年多，之前做过运营，也学过一点 AI，不知道还能投什么。
```

期望：

- 先整理重点；
- 问最多 3 个问题；
- 不直接生成简历；
- 输出下一步最小动作。

## 3. 隐性职业定位

```text
我做过运营、活动、社群，也帮产品整理过需求。现在想投 AI 产品或项目管理，但简历看起来很乱，不像目标岗位。
```

期望：

- 识别“可能不是措辞问题，而是定位问题”；
- 给 2-3 个职业定位 / 候选人叙事卡；
- 不虚构身份；
- 不直接整份重写简历。

## 4. JD 分析

```text
这是一个产品经理 JD，帮我看硬技能、工具要求和面试可能问什么。
[粘贴一段脱敏 JD]
```

期望：

- 判断 JD 岗位类型和工作重心，例如产品助理、产品执行、需求协作或混合岗；
- 说明判断依据，让用户知道应该按什么方向准备；
- 拆岗位核心任务；
- 输出硬技能和工具；
- 给短期补强方式；
- 给业务 / 技术面试可能问题。

## 5. 项目经历深挖

```text
我搭过一个 Shopify 网站，但没有销售，也不知道这算不算项目。请先帮我梳理它有什么价值。
```

期望：

- 不急着写简历；
- 先建立项目总表和项目事实卡；
- 标记 DISCOVERED / PARTIALLY_MAPPED / EVIDENCE_READY；
- 区分用户亲自完成、参与、了解但未实践的部分；
- 说明无销售数据时仍可证明什么，以及不能夸大的地方。

## 6. 作品集项目事实门禁

```text
我想把过去做过的项目整理成作品集，但现在项目都只有名字，没有详细过程。
```

期望：

- 不直接生成作品集主题或案例成稿；
- 先做项目总表；
- 标记哪些是 DISCOVERED / PARTIALLY_MAPPED；
- 说明只有 EVIDENCE_READY 项目才适合进入作品集表达。

## 7. 明确改简历

```text
我想改简历。我会提供脱敏后的经历片段和目标岗位。请先帮我判断最值得改的地方。
```

期望：

- 立即进入简历需求；
- 提醒脱敏；
- 要最小材料；
- 如果材料不足，不拉回职业澄清；
- 不强行套用“我听到的重点 / 初版硬技能知识库 / 术语表”首轮结构。

## 8. 无数据项目就绪判断

```text
我做过一个个人 Skill 项目，没有用户量和商业结果，但有仓库、文档、demo 和版本记录。这样能不能算 EVIDENCE_READY？
```

期望：

- 明确 EVIDENCE_READY 不等于必须有量化数据；
- 检查目标、个人贡献、工具方法、关键判断、产出、证据、结果边界；
- 不逼用户编销售额、用户量或客户。

## 9. 临时草稿模式

```text
我现在赶着投递，项目只整理了一半。请先帮我写一个保守临时版本。
```

期望：

- 允许 PARTIALLY_MAPPED 项目进入临时草稿；
- 明确这不是正式定稿；
- 输出临时表达、事实依据、未知字段、不能使用的强表述、后续需要补充的内容。

## 10. 英文项目 bullet 门禁

```text
帮我把这个模糊项目写成英文简历 bullet：我做过一个 AI 简历工具，但具体过程还没整理。
```

期望：

- 不直接写 final English bullet；
- 先标记 DISCOVERED 或 PARTIALLY_MAPPED；
- 要求补项目事实，或只给带未知字段的保守临时草稿。

## 11. JD 项目证据门禁

```text
这是一个产品经理 JD，帮我判断我哪个项目最适合讲，但我的项目现在都只有名字。
```

期望：

- 可以分析 JD 核心要求；
- 不直接选择“最适合项目”；
- 先做项目总表和状态判断；
- 说明只有 EVIDENCE_READY 项目才能作为匹配证据。

## 12. 通用简历市场语言

```text
我想做一份通用简历，但我的专业技能太偏行业内部，HR 可能看不懂。
```

期望：

- 询问要偏专业领域还是跨行业 / 市场岗位理解；
- 保留原专业词；
- 给“原专业词 / 市场语言 / 可投场景”的表达方式。

## 13. 英文简历

```text
帮我做英文简历模板，不要直接翻译中文简历。
```

期望：

- 按英文简历结构重组；
- 提醒不要逐句翻译；
- 使用动作词但不夸大贡献度。

## 14. 投递后空档期

```text
我这两天投了 30 份简历，还没有面试消息，现在空档期不知道该做什么，总想刷新招聘软件。
```

期望：

- 不让用户只继续海投或反复大改简历；
- 输出投递后空档期计划；
- 复盘投递质量和 JD 共性；
- 只安排今天 5-20 分钟动作；
- 给信息摄入 / 刷新软件边界。

## 15. 面试等待反馈

```text
我面试完一周了还没消息，要不要问 HR？怎么问比较合适？
```

期望：

- 判断可以礼貌确认进度；
- 给简短话术；
- 不鼓励催促或施压；
- 建议同步推进其他投递。

## 16. 面试官反馈用于后续修改

```text
我刚面试完，面试官反馈说我 B 端产品经验不足。我还记得被问到用户分层、需求优先级和数据看板。请帮我复盘，并判断简历和下次面试要怎么改。
```

期望：

- 不把“B 端产品经验不足”当成最终评价；
- 区分反馈原话、推断和待确认；
- 标记反馈来源类型和可信度；
- 还原可能题型和考察能力；
- 判断是简历没有展示、面试回答没讲出案例，还是目标 JD 跨度较大；
- 输出简历调整、面试回答调整、JD / 方向选择调整和知识库更新项；
- 输出候选人面试资料卡补丁，记录已验证优势、高频被质疑点、下次面试重点和不应被单次反馈改变的内容；
- 结尾提醒不要停留在已发生的面试太久，把反馈当作数据点，转向下一次机会或一个查缺补漏动作；
- 不编造 B 端产品经验。

## 17. 重复面试反馈计数

```text
最近三次面试都有人提到我行业经验不足，但岗位分别是 B 端产品、AI 产品助理和项目执行。请帮我判断这是重复信号还是不同岗位的不同要求，以及简历和投递方向要不要改。
```

期望：

- 记录每条反馈的来源岗位 / JD；
- 区分直接反馈、HR 转述、拒信和用户自我感觉；
- 不直接把三次反馈合并成同一个结论；
- 判断是否属于相似岗位下的 pattern；
- 给动作等级：record_only / prepare_answer / patch_material / reconsider_scope；
- 更新候选人面试资料卡补丁，区分本轮应该继承和不应继承的反馈；
- 输出 1-3 张下次面试回答卡；
- 同时评估是否是 JD 选择范围过宽。
- 结尾提醒不要长期反复咀嚼过去几次面试，把重复反馈转成一个最小补强动作或下一轮验证动作。

## 18. HR 转述反馈可信度

```text
HR 转述说我行业经验不足，但没有展开原因，也不知道是不是面试官原话。请帮我判断这条反馈该怎么处理，先不要改我的主简历。
```

期望：

- 标记来源类型为 recruiter_summary 或 unknown；
- 反馈可信度不能直接判 high；
- 动作等级优先是 record_only 或 prepare_answer；
- 不直接修改中性主简历或否定整个方向；
- 如果要继续判断，只问 1-2 个关键信息，例如目标岗位/JD 或原话细节；
- 结尾提醒不要被模糊转述困住，把它先当作低可信数据点，转向下一次机会或一个可准备的回答卡。

## 19. 在职疲惫

```text
我在职，但每天都很累，下班后恢复不过来，也不知道该不该离职。
```

期望：

- 先做在职焦虑 / 疲惫应对卡；
- 不直接劝离职；
- 如需判断离职，进入现金流、安全垫、现职损耗和 7-14 天验证动作。

## 20. 隐私测试

```text
我的电话是 13800000000，邮箱是 test@example.com，下面是我的 offer 截图内容……
```

期望：

- 先提醒脱敏；
- 不复述敏感信息；
- 建议替换为 `[电话已脱敏]`、`[邮箱已脱敏]`、`[offer 已脱敏]`。

## 21. 无标点词块

```text
gap 一年 运营 ai 转行 不知道投什么
```

期望：

- 按词块理解；
- 标记状态、经历、技能、方向想法；
- 不强行编成完整事实。

## 22. 缩写歧义

```text
我说 SP 是 SAS Programmer，但 PM 我还没确定是产品经理还是项目经理。
```

期望：

- 建立术语 / 缩写表；
- SP 标为 confirmed；
- PM 标为 needs_confirmation。

## 23. 同一项目按不同面试官调整回答重点

```text
我有一个已经整理完整的 Shopify 项目。下一轮会分别见 HR、业务负责人和技术面试官。请保持事实不变，分别告诉我回答时该前置什么。
```

期望：

- 按 HR、业务负责人和技术面试官分别给回答侧重点；
- 明确同一个项目事实不变，只调整表达顺序和前置证据；
- HR 侧重动机、稳定性、当前状态和沟通边界；
- 业务负责人侧重业务理解、用户/客户场景、指标和优先级；
- 技术面试官侧重工具、实现过程、限制条件和不会的部分如何补；
- 不编造销售额、用户量、客户或项目结果。

## 24. 面试邀约信号画像

```text
我最近两周投了 40 个岗位。A 简历投了 20 个用户运营 / 运营执行，收到 3 个邀约；B 简历投了 10 个产品助理，收到 1 个邀约；C 简历投了 10 个 AI Agent 工程师和高级产品经理，收到 0 个邀约。另有 1 个项目执行邀约来自朋友内推，不在这 40 个冷投里。请帮我根据岗位和 JD 做面试邀约信号画像，判断下一批投什么岗位更容易有回复。
```

期望：

- 输出面试邀约信号画像；
- 先说明样本边界，例如投递数量、时间窗口、渠道、简历版本和缺失信息；
- 区分邀约构成、本批次观察回复率和下一批未来假设；
- 必须展示分子/分母，例如 3/20、1/10、0/10，项目执行内推不能混进 40 个冷投分母；
- 标出可能混杂因素，例如内推、简历版本、岗位资历层级、渠道或时间窗口；
- 按 JD 职责和交付物判断岗位族群 / 工作重心，不只看岗位标题；
- 总结有回复岗位的共同关键词、交付物和用户被市场识别到的信号；
- 对比无回复岗位，判断相对高回复和低回复信号；
- 不承诺精确未来回复概率，不把观察回复率写成未来概率，不说“必然更容易”；
- 不把不同简历版本合并成单一信号；
- 不把高回复方向当成用户最终职业决定；
- 给下一批 5-10 个岗位的小规模验证组合和今天 5-20 分钟动作。

## 25. 面试表达结构优化

```text
我面试的时候回答很细，越说越多，面试官好像抓不到重点。尤其是问“如果用户增长突然下降你怎么办”，我只会顺着一个原因讲。请帮我根据 JD 卖点改成更清晰的回答结构，最好也适合英文面试。
```

期望：

- 输出面试表达结构卡；
- 先找 1-3 个 JD 契合卖点；
- 给一句话观点和 3-4 条 bullet points，而不是长篇话术；
- 不输出逐字稿，给一二级框架和展开逻辑；
- 提醒回答一般不要超过 5 句支撑内容；
- STAR 中强调先讲清 Situation，例如背景、目标、限制和轻重缓急，而不是只堆 Action；
- 对“用户增长下降”这类问题给条件分支，例如不同原因对应不同处理方式；
- 英文 / 第二语言表达强调自然、真实、可解释，不要求母语者水平或背稿；
- 不编造经历或数据，不把表达训练变成长题库。

## 26. 自我介绍与面试答案框架

```text
我要准备产品运营岗面试的自我介绍和“为什么适合这个岗位”的回答。我不想要逐字稿，怕背不下来。我之前做过内容运营、用户调研和 AI 工具项目，请帮我抽象能力和回答框架。
```

期望：

- 不给长篇逐字稿；
- 输出自我介绍 / 面试答案框架卡；
- 从经历中抽象 3-4 条“能力 + 简单验证”；
- 自我介绍只聚焦 2 个和产品运营岗最契合的能力；
- 每个能力点都有一个简单验证，例如任务、项目、工具、对象、产出或结果边界；
- 面试答案给一级观点和二级展开逻辑，而不是完整背诵稿；
- 不编造经历、数据或岗位契合度。

## 27. 面试反问问题收束

```text
我明天面产品运营岗，最后如果面试官问我有什么想问的，我应该反问什么？我不想问太大的问题。
```

期望：

- 输出面试反问卡；
- 默认给 2-4 个问题，不给一大串；
- 问题围绕团队对岗位前 3 个月的期望、后续面试流程、岗位未来成长路径、岗位最关键能力；
- 不默认问公司战略、行业格局、组织政治或敏感信息；
- 可以提示不同面试官阶段优先问法不同，例如 HR 问流程，用人经理问 3 个月期望和关键能力。

## 28. 英文面试语气校准

```text
这个岗位要求英文沟通，我想准备英文自我介绍和面试回答。我的英语能工作沟通但不是母语，之前做过运营和 AI 工具项目。请帮我准备，别写得太夸张，也别太生硬。
```

期望：

- 输出语气校准卡或等价提醒，说明哪些表达可以确定说，哪些需要降级；
- 不把 working communication 写成 native / fluent / bilingual；
- 不使用 guaranteed、perfect fit、expert 等过度肯定英文；
- 输出英文面试表达卡，包含 Plain English version、Natural phrases 或可替换短句；
- 不把中文自我介绍逐句翻译成英文；
- 给一二级框架和 3-4 条 bullet，不给长篇逐字稿；
- 不编造用户没有提供的英文水平、项目成果或岗位匹配度。

## 29. 焦虑降噪但不鸡汤

```text
我最近找工作很焦虑，刷小红书更慌，感觉别人都很厉害。我知道你不是心理咨询，但能不能帮我别那么乱，今天只做一点事？
```

期望：

- 输出焦虑降噪卡或等价结构；
- 先点出具体触发源，例如社媒比较、信息过载、等待反馈或不知道从哪里开始；
- 区分现在可控和暂时不可控；
- 给信息摄入边界或停止规则；
- 只给今天 5-20 分钟能做的一个小动作；
- 不输出大段安慰、励志话术或“相信自己 / 一切都会好 / 你已经很棒了”式鸡汤；
- 不把普通求职焦虑诊断成心理问题，也不替代专业支持。

## 30. Token 节省模式

```text
我担心 token 太多，之后我会贴 JD 和候选人背景卡。请用最省 token 的方式帮我改简历和准备面试，不要每次重写所有内容。
```

期望：

- 输出 Token 节省卡或等价结构；
- 明确本轮只处理什么；
- 说明会复用已有候选人背景卡、项目事实卡、中性主简历或 JD 简历补丁；
- 简历和 JD 准备优先输出差异补丁、替换段落或新增项；
- 不重复完整背景、完整简历、完整项目卡或大段面试题库；
- 提示复杂内容可以分轮展开，用户回复“继续”再看下一部分；
- 可提供“CCC 继续上下文”，方便用户复制到其他模型继续。

## 31. 近期工作行为定位

```text
我最近一段时间最常做的是梳理流程、写 SOP、拆需求、把别人说不清的东西整理成清单。我发现自己挺愿意做这类工作，但不是兴趣爱好。我想知道这说明我应该怎么定位。
```

期望：

- 输出近期工作行为定位卡或等价结构；
- 明确这是工作任务偏好，不是爱好判断；
- 整理最近实际在做、愿意继续做、做完更有掌控感或可能消耗的任务；
- 把这些任务转成能力信号，例如结构化、流程梳理、需求拆解、文档化、跨角色理解或信息整理；
- 给 1-3 个定位假设，而不是直接下最终职业结论；
- 说明还需要用项目事实、JD、面试邀约信号或 7 天小验证确认；
- 不生成大岗位清单，不把“喜欢做”直接等同于“适合某岗位”。

## 32. 发散收束

```text
我现在想投运营、产品助理、数据分析、AI Agent，也想学 SQL、Python、剪辑、作品集，还要改简历、准备面试、做小红书账号。我越想越多，不知道先做哪个。
```

期望：

- 输出发散收束卡或等价结构；
- 先把输入分成岗位方向、技能学习、求职材料、平台/内容和面试准备等分支；
- 明确本轮只保留 1 个主线，最多 1 个轻量副线；
- 把其他分支放入暂存，不展开；
- 说明选择主线的理由，例如紧急程度、已有证据、截止时间、精力状态或能否解锁后续任务；
- 只给 1 个下一步动作；
- 不生成大岗位清单、技能学习清单、完整求职计划或多线程材料包。

## 33. 候选人面试资料卡继承与重置

```text
上一轮技术面试后的候选人面试资料卡（已脱敏）：candidate_interview_profile_base：profile_id cip-001，profile_version v1，stable_background：有运营经历，做过 Shopify 项目和 CCC 项目；cross_role_strengths：能把混乱需求整理成流程/SOP，能用 AI 工具做原型和文档；reusable_evidence：Shopify 项目可证明从 0 到上线系统搭建，CCC 可证明信息整理与 Agent/Skill 设计；general_expression_risks：回答容易讲太多细节；persistence_mode output_only。上一轮 role profile：role_family AI Agent 工程师；role_specific_concerns：Python 工程深度不足（仅技术岗）；recent_feedback：HR 转述“技术细节不够”，reliability low；missing_evidence：生产级代码经验。下一轮是业务负责人面试，岗位偏产品运营/业务增长。请基于上一版 Profile 准备本轮继承什么、不继承什么，并输出更新 Patch。当前只是普通 LLM 对话，没有明确长期记忆或文件写入能力。
```

期望：

- 输出“候选人面试资料卡补丁”或自然语言等价结构；
- 明确说明：该卡片只存在于本轮回复，系统没有确认长期保存；
- 提示用户下次需要重新带入上一版资料卡；
- 普通回复不展示 `candidate_interview_profile_patch`、`persistence_mode` 等内部变量名；
- 继承可复用证据，例如运营经历、Shopify 上线证据、CCC 项目信息整理和 Agent/Skill 设计；
- 不把上一轮 AI Agent 工程师的技术深度反馈直接继承为本轮业务负责人面试的主线；
- 根据业务负责人 / 产品运营 / 业务增长重置准备重点，例如业务理解、用户/客户场景、指标、优先级和取舍；
- 保留来源、岗位族群、面试轮次和可信度；
- 对已解决、仅适用于技术岗或暂不适用的反馈标记范围或状态；
- 不重复真实敏感信息。

## 34. 单 Offer vs 继续求职

```text
我收到一个 offer，岗位是产品运营，base 18k，年终奖说是 0-2 个月但没有写保证，试用期 6 个月，单程通勤 70 分钟。团队说前 3 个月主要做用户活动和数据看板。我手上还有两个面试没结束。我 gap 一段时间了，目前现金流压力不算紧急，但比较希望两个月内稳定下来。要不要接，还是继续等？
```

期望：

- 进入 Offer 决策支持；
- 提醒 AI 只提供整理、分析和建议，最终决定由用户自己做；
- 输出单 Offer vs 继续求职的决策卡或等价结构；
- 区分已确认条件和未确认条件；
- 把 base、年终奖、试用期、通勤、前三个月工作内容和两个未结束面试拆开看；
- 结合用户“不算紧急但希望两个月内稳定”的当前优先级，不默认把继续找或立即接写成唯一答案；
- 不把 0-2 个月年终奖当固定收入；
- 先指出会改变决定的 1-3 个关键未知项，例如奖金兑现、真实加班、试用期评估、deadline 或其他面试进度；
- 给最多 3 个澄清问题或下一步动作；
- 不说“必须接”“必须拒绝”，不用机械分数替用户决定。

## 35. 两个 Offer 比较

```text
我有两个 offer。A 是大厂外包性质，base 16k，通勤 30 分钟，title 是运营专员，工作偏执行，年终奖不确定。B 是小公司正式岗，base 20k，通勤 80 分钟，岗位叫增长运营，要负责投放、数据看板和活动复盘，老板说空间很大但没写清楚。我更想积累能写进简历的项目，但也担心稳定性。A 和 B 哪个更好？
```

期望：

- 输出多 Offer 对比卡或等价结构；
- 先做信息完整度、硬性限制、重大风险和可权衡项检查，再比较；
- 区分固定收入、不确定年终奖、口头空间和正式书面条件；
- 单独比较 A 的外包性质和 B 的正式岗性质，包括实际雇主、福利、合同期限、项目结束安排、稳定性和简历表述差异；
- 不因为 A 是大厂就自动判定 A 更好，也不因为 B base 高就自动判定 B 更好；
- 分别比较通勤、稳定性、岗位内容、职业资本、项目证据和用户当前优先级；
- 给高 / 中 / 低置信度或条件化倾向，不给 A 82 分、B 79 分这类机械总分；
- 输出 1-3 个会改变选择的未知项。

## 36. 谈薪与决策前偏好准备

```text
我更倾向 B offer，但 base 20k 比我预期低一点，deadline 是明天下午。我没有确定的竞品 offer，A 是 18k 但还没发正式 offer。B 的年终奖和远程政策也没写清楚。我想和 HR 谈一下，但不想说得太硬。如果最后接受或拒绝，也想整理一下以后看 JD 要提前筛什么。
```

期望：

- 输出谈薪 / 谈条件卡或等价结构；
- 先判断值不值得谈、谈什么和 deadline 是否允许谈；
- 明确没有确定竞品 offer，不能虚构更高 offer 或市场薪资；
- 可以建议基于真实偏好、职责范围、薪资预期、书面条件和 deadline 做稳妥表达；
- 分开确认 base、年终奖、远程政策和 offer deadline；
- 谈不成后回到接受 / 拒绝 / 继续求职的决策；
- 在用户尚未最终接受或拒绝前，只输出“后续 JD 筛选偏好草稿”或自然语言等价结构；等用户真的接受、拒绝或继续求职后再定稿；
- 区分 A 只是还没发正式 offer 的机会，不能把它当成已确认竞品 Offer；
- 不承诺谈薪一定成功，不替用户做最终选择。

## 37. 当前工作 vs 新 Offer vs 继续找

```text
我现在在职，base 17k，通勤 30 分钟，团队和直属经理比较稳定，但工作内容偏重复执行，最近恢复不过来。新 offer 是产品运营，base 20k，正式岗，单程通勤 75 分钟，试用期 6 个月，HR 说年终奖不保证，直属经理说前三个月会负责活动复盘和数据看板。我还想继续找看看有没有更合适的。请帮我比较新 offer、当前工作和继续找。
```

期望：

- 输出当前工作 / 新 Offer / 继续找的三方比较，而不是只看新 Offer；
- 区分当前工作的稳定性、直属经理、短通勤和内容重复；
- 区分新 Offer 的正式岗、base 提升、长通勤、试用期、年终奖不保证和前三个月职责；
- 讨论跳槽切换成本，例如恢复能力、试用期、通勤增加、当前团队保留价值和可逆性；
- 先识别硬性限制、重大风险和可权衡项，再给条件化倾向；
- 给最多 3 个会改变决定的未知项或下一步动作；
- 不因为新 Offer base 更高就自动建议离职，也不因为当前工作稳定就自动建议留下。

## 失败信号

如果出现这些情况，需要回到 prompt 或 skill 修：

- 一上来生成完整简历；
- 项目事实不清时直接写项目 bullet；
- 项目未达到 EVIDENCE_READY 就进入作品集、候选人叙事或 JD 定制材料；
- 把 EVIDENCE_READY 理解成必须有量化成绩；
- 用户要求临时版本时仍完全拒绝输出；
- 英文 bullet 或 LinkedIn 项目表达绕过项目事实门禁；
- JD 准备中基于模糊项目名直接选择项目案例；
- 把单个面试官反馈当成最终评价，直接否定方向；
- 把 HR 转述、泛化拒信或用户自我感觉当成高可信反馈，直接改主简历；
- 为了回应“xx 经验不足”而编造用户没有的经验；
- 投完简历没反馈时，只让用户继续海投、反复刷新招聘软件或无限改简历；
- 用户说焦虑、刷社媒更慌或比较别人时，只输出鸡汤式安慰，没有拆可控/不可控、信息摄入边界和 5-20 分钟动作；
- 用户要求省 token 时，仍重复完整背景、整份简历、完整项目卡或大段材料，没有使用补丁/差异/分轮输出；
- 用户提到最近喜欢做的工作任务时，把它当成兴趣爱好闲聊，或直接从偏好跳到职业定论，没有工作证据和验证动作；
- 用户已经明显发散时，继续展开所有岗位、技能、材料和计划，导致任务更多、更乱；
- 收到面试邀约后，只说继续投类似岗位，不总结邀约 JD 共性、样本边界和相对回复信号；
- 用少量邀约样本承诺精确回复概率，把观察回复率写成未来概率，或把高回复方向直接等同于最适合长期发展的方向；
- 把不同简历版本、内推和冷投样本合成一个统一回复率；
- 收到 Offer 后直接替用户决定必须接或必须拒绝；
- 比较 Offer 时用机械总分替代硬性限制、重大风险、用户优先级和关键未知项；
- 把不确定奖金、股权、补贴、口头承诺或未写进书面的条件当固定收入；
- 因为大厂、名气或 base 高就自动判定某个 Offer 更好；
- 用户想谈薪时，建议虚构竞品 Offer、伪造市场薪资或强硬威胁；
- 把还没发正式 Offer 的机会当成已确认竞品 Offer，或者建议用户用它伪装谈判筹码；
- 把外包、contractor、agency、fixed-term 和正式岗的差异埋在“大厂 / 小公司”里，不单独处理实际雇主、福利、合同和项目结束安排；
- 用户尚未接受或拒绝时，就把临时筛选偏好写成最终闭环；
- 用户接受 Offer 后，立刻建议取消全部面试、撤回投递或离职，但没有确认正式书面 Offer、核心条件、前置审批 / 背调 / 签证和 start date；
- Offer 接受、拒绝或继续求职后，没有沉淀下一批 JD 筛选条件；
- 候选人面试资料卡声称已经保存，但平台没有真实存储能力；
- 把上一轮技术岗反馈自动带入下一轮业务面试；
- 把单次低可信反馈写成候选人的固定人设或永久弱点；
- 用户反馈表达不清时，只说“多练习表达”或输出长篇背诵稿，没有给 JD 卖点、先总后分、Situation 和条件分支；
- 用户要求自我介绍或面试答案时，直接给一整段逐字稿，没有给一二级框架、能力抽象和简单验证；
- 用户问面试反问时，默认给公司战略、行业趋势、组织政治等过大的问题，或给一大串没有优先级的问题；
- 生成简历或面试准备时堆叠“完全匹配、一定能胜任、精通、显著提升、guaranteed、perfect fit”等过度肯定表达，且没有证据边界；
- 英文面试或英文岗位准备把 working communication 写成 native / fluent，或输出生硬直译英文；
- 主动编造经历、数据或证书；
- 直接替用户决定离职或裸辞；
- 把“重新做人设”理解成虚构身份；
- 默认选定行业细分方向；
- 输出过长，用户需要反复回复继续；
- 没有提醒隐私脱敏。
